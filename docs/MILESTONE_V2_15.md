# V2.15 — Guided invoice scenarios

How it works now has three tabs: Entire workflow, Agentic workflow and Try a scenario. The first two still come from `dist/HOW_IT_WORKS.md` with one `---` divider. The third is a live, read-only catalogue built from the loaded portfolio, public scenario summaries and this browser’s saved cases. `dist/guide-ui.js` contains the short walkthrough descriptions for all fifteen seeded scenarios; other invoices receive a generic walkthrough.

Each row shows the invoice/customer, scenario explanation, suggested test and current-state guidance. Open scenario closes the guide, opens that exact invoice and focuses a persistent Suggested test notification. This also works for preventive or no-balance invoices outside the currently visible queue; filters must not silently substitute another invoice. Opening never starts a run, creates a case, calls an LLM or sends email. Existing case history is retained.

Every invoice popup offers Use suggested reply and a category picker: Promise to pay, Claims already paid, Dispute invoice, Request invoice copy, and Other / human review. Seeded invoices also default to their tailored scenario response. The future-promise example uses a date seven days after the current simulation date. Suggestions fill editable text only; Send simulated reply remains a separate explicit action. Before a saved case exists, the same controls prepare an unsent local draft and explain that Run collections enables processing. A prepared draft carries into the saved case; no synthetic reply is auto-submitted. Drafts remain in page memory, not across reload.

Guidance reflects current saved state, including a pending promise approval, an already recorded promise, a fully matched payment or active processing. Outcomes still come from backend policy and evidence. Reply interpretation requires the optional LLM; disabled, capped or invalid model calls require manual review. Generic paid replies do not fabricate payment references, and generic document requests do not guarantee a document exists. Trying a reply does not clear dispute/contact/delivery restrictions or change source AR. Real email remains the fixed project test inbox with existing approvals and budgets.

UI files: `dist/guide-ui.js`, `app.js`, `invoice-ui.js`, `index.html`, `styles.css`. Backend changes version metadata only: app v2.15 / UI workflow-16. No new SQL, packages, settings, external services or paid capabilities. SQL014 remains the existing checkpoint prerequisite; its successful live retry has not been confirmed here.
